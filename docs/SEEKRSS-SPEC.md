# SeekRSS v0.1 — implementation contract

Single administrator, multiple RSS/Atom feeds, Web + Telegram configuration using one SQLite store. Fork UI/CSS from ljnchn/NodeSeeker-docker (MIT); retain notices. No registrations, multi-tenant user model, AI, proxy/IP rotation or full-text scraping. Original source baseline b5497569704f07f0e239dca84061081bb6f09e14.

## Modules and ownership

New implementation lives in src/seekrss/. Legacy upstream routes/services are not mounted by the new server. Existing upstream CSS is retained. Use the Bun version pinned in package metadata and the Dockerfile. Follow strict vertical TDD: one failing test, run, minimal implementation, run. Tests: bun test tests/. Shared contracts live in types.ts; core persistence and validation in store.ts/service.ts/api.ts, collector in network.ts/parser.ts/engine.ts/formatter.ts, Bot in bot.ts, and UI in ui.tsx/public assets. Public history starts with a current-source snapshot; do not reintroduce inherited history or runtime credentials.

## Canonical types

See src/seekrss/types.ts; preserve identifiers. Epoch timestamps are milliseconds; intervals are seconds. Feed fields expose both interval_seconds (requested) and effective_interval_seconds (runtime conservative limit/host floor), last/next/cooldown/error state. Feed IDs/rule IDs/target IDs are independent integers. Rule kinds keyword/combo/block/blockcombo, terms: string[]; keyword/block hold one term; combo/blockcombo at least two. Independent include rules OR, terms within combo AND, blocks win. Scope title/summary/all (all covers title+summary+author+category). feed_id null means all sources. Empty include rules mean no pushes, not push-all. Case-insensitive NFKC matching. No eval or unbounded regex.

## Store and AppService contract

Core exports class Store (store.ts), constructor(path:string), db public bun:sqlite Database, close(). Constructor runs idempotent schema migrations, WAL+foreign_keys+busy timeout. Atomic unique keys and outbox transactions.

Methods sync unless noted:
- listFeeds():Feed[]; getFeed(id):Feed|undefined; saveFeed(input:Partial<Feed>&{name?:string,url?:string}, id?:number):Feed; deleteFeed(id):void.
- updateFeedRuntime(id:number, patch:Partial<Feed>):void (allowlist runtime fields only).
- listRules():Rule[]; saveRule(input:RuleInput,id?:number):Rule; deleteRule(id):void; setRuleEnabled(id,enabled):Rule.
- listTargets():Target[]; saveTarget(input:TargetInput,id?:number):Target; deleteTarget(id):void.
- getSettings():Settings (bot_token always '' externally); getSecretToken():string; saveSettings(input:Partial<Settings>&{bot_token?:string}):Settings. Encrypt token at rest with AES-GCM using a data-dir key file (mode 0600) or SECRET_KEY env. Redact via all API reads. Preserve token on omitted/empty field; explicit clear_token boolean may remove.
- getConfigVersion():number; bump on config writes. getSettings internally still returns redacted token.
- ingestEntries(feedId:number,entries:ParsedEntry[]):{inserted:number,queued:number}; first successful fetch initializes feed and baselines existing entries unless backfill=true. In one transaction persist all new entries, matches, blocks and unique deliveries per entry+target. Use real shared matching helper exported from service.ts: evaluateEntry(entry,rules,feedId):{matched:Rule[],blocked:Rule[]}. paused suppresses new delivery jobs but continues archiving entries, resume only future entries.
- listEntries(options?:{search?:string,feed_id?:number,matched?:boolean,limit?:number,offset?:number}):{items:Entry[],total:number}; newest first by discovered_at,id. Includes feed_name, matched_rules:string[], blocked_rules:string[], deliveries array if practical.
- listDeliveries(limit?:number):Delivery[]; recoverDeliveries():void resets stranded sending->pending on startup.
- claimDelivery(now?:number):Delivery|undefined atomic pending/retry due -> sending, increments attempts; includes entry and target joined.
- finishDelivery(id:number,patch:{status:'sent'|'retry'|'failed';error?:string;next_attempt_at?:number;message_id?:number;sent_at?:number}):void.
- getStatus(): object with counts, config_version, recent deliveries; exportData(): nonsecret config JSON optional.

AppService constructor(store:Store), exposes store and same CRUD methods (delegation allowed); validates input, URL schemes, intervals>=1, term counts/lengths, target IDs and settings. getSettings/saveSettings, list/get/save/deleteFeeds, list/save/deleteRules, setRuleEnabled, list/save/deleteTargets, getStatus, listEntries, listDeliveries. `testRule(input:{text:string,feed_id?:number}):{matched:Rule[],blocked:Rule[],would_push:boolean}`. All external mutation surfaces use this class. No network in constructor. Runtime reads Store live; no stale configuration snapshots. Error strings may be Chinese; do not leak SQL, token, URL secrets.

## HTTP API contract (core)

export createApi(service:AppService, hooks?:{testFeed?:(id:number)=>Promise<unknown>;testTelegram?:()=>Promise<unknown>;preview?:()=>unknown}): Hono.
Routes mounted at /api in server. createApi handles own middleware authentication except /auth/status,/auth/setup,/auth/login; protect ALL feed contents too.
GET /auth/status -> {initialized:boolean,authenticated:boolean,csrf?:string}; POST /auth/setup {username,password,setup_key} one administrator only, verify env SETUP_KEY or generated data-dir setup.key, passwords >=12, setup race atomic. POST /auth/login; POST /auth/logout. Session cookie HttpOnly SameSite=Strict, Secure when HTTPS; random hashed durable session, expiry, CSRF token. Mutations require X-CSRF-Token and same-origin Origin when supplied. Limit auth brute force using actual peer identity provided by parent or one bounded global limiter (do not trust forwarded headers).
GET/POST /feeds; PUT/DELETE /feeds/:id; POST /feeds/:id/test through hook and shared limiter (never direct fetch).
GET/POST /rules; PUT/DELETE /rules/:id; POST /rules/test {text,feed_id?}.
GET/POST /targets; PUT/DELETE /targets/:id.
GET/PUT /settings (token redacted + token_configured boolean).
GET /entries?search=&feed_id=&matched=true&limit=&offset= -> {items,total}; GET /deliveries; GET /status; POST /telegram/test via hook; GET /preview via hook.
Successful API payload {ok:true,data:...}; failures {ok:false,error:string} proper 4xx/5xx. Auth status follows same envelope. Request size bound 64 KiB. Enforce revision optimistic writes where feasible, at minimum return config_version. No public webhook accepting unauthenticated config. All page JS uses these exact envelopes.

## Engine contract (collector)

export class Engine(store:Store, options?:{fetcher?:typeof fetch; now?:()=>number; allowPrivateForTests?:boolean; telegramTransport?:(token:string,method:string,payload:unknown)=>Promise<any>}) with start(), async stop(), async tick(), async pollFeed(id:number), async sendPending(), status(), async testTelegram(), preview(). Do not start timers in constructor. tick may run feeds concurrently across unrelated hosts but one in-flight source and per-host shared request budget. Reuse single engine for tests/manual/scheduled. interval requested can be 1 sec; effective floor >= settings.host_min_interval_seconds (default 10, administrator can set 1 after reviewing publisher policy). NEVER claim safe sustained rate from absence of 429. Host cooldown durable via SQLite separate table if needed; domain aliases policy documented. 429/503 honor numeric/date Retry-After, durable exponential backoff; 403 stops source with actionable error. Network validates SSRF-safe http(s), resolve all addresses, reject private/link-local/loopback/metadata etc incl redirects; prevent DNS rebinding with pinned resolution or equivalent robust dispatcher. Test override never exposed by API/env in production. Bound response 2MiB incl after decompression, timeout covers body, max 3 redirects. ETag/Last-Modified only when available, 304 still consumes budget, don't advance initialized on parse/fetch failure. XML parse real RSS/Atom parser (not regex), disable entities; respect safe links. HTML sanitization/escaping.

formatter exports renderMessage(entry:ParsedEntry & {feed_name?:string}, matchedRules?:string[], settings?:Partial<Settings>):{text:string,parse_mode:'HTML',reply_markup?:object,link_preview_options:object}; escape all publisher content, optional missing fields omitted, max safe Telegram length; bold matching terms via safe escaped text if feasible. Compact/summary templates, no article fetch.

Delivery worker checks live paused/token/targets; no token does not mark jobs sent or spin infinitely. Default API https://api.telegram.org; transport injectable only in constructor. 429 obey retry_after, retry transient network/5xx with bounded attempts, fail permanent errors; per-chat and global sending limits, no batch delay in normal low-load case. Store message ID and exact sent time. Don't wait for send in RSS polling loop. Backlog can exceed three-second target: visible in status. Telegram accepted is NOT mobile received.

## Bot contract (bot owner)

export class BotController(service:AppService, options?:{transport?:(token:string,method:string,payload:unknown)=>Promise<any>;engine?:{pollFeed:(id:number)=>Promise<unknown>;testTelegram:()=>Promise<unknown>}}) with async start(), async stop(), async sync(), async handleUpdate(update:any):Promise<void>, status(). Uses service.getSettings().admin_telegram_id to authorize exact stable user ID AND private chat; no admin ID means fail closed. Token from service.store.getSecretToken(). Long polling start only with token+admin id; runtime token changes restart safely, backoff API errors. Register supported commands in correct private scope, read them back, expose status registration state; don't overwrite active webhook without explicit error/permission.
Commands: /start /help; /add terms comma separated -> independent keyword rows; /combo terms -> one AND group; /block terms -> independent block rows; /blockcombo terms -> AND group; /list; /on ID /off ID /del ID; /feedadd URL [name] /feeds /feededit ID (wizard) /feeddel ID /interval ID seconds /feedpause ID /feedresume ID; /pause /resume (push-only, while paused archive but no backlog generated); /status /history /test [text]; /targets /targetadd chat_id [label] /targetdel ID; /cancel. No-argument add/combo/block/blockcombo/feedadd commands use expiring cancelable wizard. Persistent mobile reply keyboard routes same actions. Never accept token/password from chat; point to protected Web settings. Target add private identity or Telegram admin+bot permission verification for groups/channels using Bot API. Destructive actions confirm if practical. Catch errors and respond with exact actionable message, don't swallow.
